## 1. Обзор

### 1.1. Назначение

ИКТК — интегрированный конструкторско-технологический комплекс с программой-оркестратором («дирижёром»), которая анализирует процесс автоматизированного проектирования методов и средств создания продукции и последовательно передаёт управление профильным программам (CAD, CAM, CAPP, нормирование, оснастка, ЧПУ, термообработка, покрытия, сборка, контроль).

### 1.2. Ключевые возможности

- Оркестрация ТПП с точками контроля (смешанный режим: автоматически + ручное подтверждение).
- Поддержка ТП: литьё, объёмная штамповка, механообработка (включая ЧПУ), нормирование, сборка, вспомогательные операции.
- Интеграция с CAD/CAM: Siemens, Dassault, T-FLEX, КОМПАС.
- Анализ сборочных единиц (BOM).
- Проектирование ТП и оснастки для деталей и сборки.
- Ввод оборудования предприятия и подбор оборудования под ТП.
- Gap-анализ и рекомендации при дефиците оборудования.
- Версионность, аудит, откат.
- Веб-клиент + Electron-оболочка.

### 1.3. Архитектурный стиль

**Гибридная архитектура:**
- Оркестратор и ядро — микросервисы.
- Тяжёлые технологические модули (CAD/CAM/CAPP) — отдельные приложения.
- Взаимодействие: REST/gRPC + очереди сообщений (RabbitMQ).
- Оркестрация: конечный автомат (Spring StateMachine).
- Развёртывание: Docker + Kubernetes.
- CI/CD: GitLab CI.

## 2. Архитектурные принципы

1. **Единая точка входа** — API Gateway маршрутизирует все клиентские запросы.
2. **Разделение ответственности** — каждый сервис решает одну задачу.
3. **Асинхронность** — длительные операции через очереди.
4. **Идемпотентность** — повторная обработка безопасна (correlationId).
5. **Версионность по умолчанию** — снапшоты сущностей в `entity_versions`.
6. **Append-only аудит** — `audit_log` защищён триггерами.
7. **Точки контроля** — смешанный режим оркестрации.
8. **Расширяемость** — новые модули подключаются через API и очереди.
9. **Наблюдаемость** — метрики, логи, трассировка, алерты.
10. **Импортозамещение** — ядро отечественное, интеграции — любые.
