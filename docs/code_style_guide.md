# Code Style Guide — стандарты кода ИКТК

**Проект:** Интегрированный конструкторско-технологический комплекс (ИКТК)  
**Кодовое имя:** `iktk-complex`  
**Версия:** 1.0  
**Статус:** обязательный к исполнению

---

## 1. Назначение

Документ описывает единые стандарты написания кода для всех модулей ИКТК:

- **Backend (Java):** Spring Boot сервисы, микросервисы, общие библиотеки.
- **Frontend (TypeScript + React):** веб-клиент, Electron-оболочка.
- **SQL:** миграции, схемы, запросы.
- **Docker / Kubernetes / CI:** инфраструктурный код.
- **Документация:** Markdown, OpenAPI.

Соблюдение стандартов обеспечивает:
- читаемость и сопровождаемость;
- единообразие в команде;
- снижение количества ошибок;
- автоматизированную проверку в CI/CD;
- лёгкий онбординг новых разработчиков.

---

## 2. Общие принципы

1. **Ясность важнее краткости.** Код читается чаще, чем пишется.
2. **Явное лучше неявного.** Никакой «магии».
3. **Единообразие важнее личных предпочтений.** Стандарт — закон.
4. **Малые изменения — лёгкий ревью.** Один PR — одна задача.
5. **Комментарии — «почему», а не «что».** Код должен говорить сам за себя.
6. **Тесты обязательны.** Нет тестов — нет мержа.
7. **Безопасность по умолчанию.** Никаких секретов в коде.
8. **Идемпотентность.** Повторный запуск не ломает систему.
9. **Наблюдаемость.** Логи, метрики, трассировка.
10. **Совместимость.** Обратная совместимость API и схем БД.

---

## 3. Общие правила для всех языков

### 3.1. Кодировка и переводы строк

- **Кодировка:** UTF-8 без BOM.
- **Перевод строки:** LF (Unix-стиль), даже на Windows.
- **Отступ:** пробелы (не табы). Размер — по языку (см. ниже).
- **Конец файла:** перевод строки обязателен.
- **Trailing whitespace:** запрещён.

Настройка `.editorconfig` в корне:

```ini
root = true

[*]
charset = utf-8
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true
indent_style = space
indent_size = 4

[*.{ts,tsx,js,jsx,json,yml,yaml}]
indent_size = 2

[*.md]
trim_trailing_whitespace = false

[Makefile]
indent_style = tab
