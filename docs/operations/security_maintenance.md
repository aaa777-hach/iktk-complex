# Security Maintenance — регламент сопровождения ИБ ИКТК

**Проект:** Интегрированный конструкторско-технологический комплекс (ИКТК)  
**Кодовое имя:** `iktk-complex`  
**Версия ТЗ:** `final_TZ.md` (ред. 3)  
**Версия документа:** 1.0  
**Статус:** актуально  
**Ответственный:** Специалист по ИБ

---

## 1. Назначение

Документ описывает регламент сопровождения информационной безопасности ИКТК после ввода в эксплуатацию. Используется для:

- поддержания требуемого уровня защищённости;
- регулярного аудита и обновления политик;
- реагирования на инциденты ИБ;
- управления уязвимостями;
- контроля доступа и прав;
- соблюдения требований регуляторов.

**Область действия:** все сервисы ИКТК, инфраструктура (K8s, PostgreSQL, RabbitMQ, MinIO), аутентификация, авторизация, аудит, сетевые политики, секреты, CI/CD.

---

## 2. Принципы сопровождения ИБ

1. **Defense in depth** — многоуровневая защита.
2. **Least privilege** — минимальные привилегии.
3. **Zero trust** — не доверять по умолчанию.
4. **Continuous monitoring** — постоянный мониторинг.
5. **Regular audit** — регулярный аудит.
6. **Timely patching** — своевременное обновление.
7. **Incident response** — готовность к инцидентам.
8. **Documentation** — фиксация всех решений.
9. **Accepted risks** — управление принятыми рисками.
10. **Compliance** — соответствие требованиям.

## 3. Область безопасности

### 3.1. Компоненты, требующие сопровождения

| Компонент | Зона ответственности | Критичность |
|---|---|---|
| API Gateway | Аутентификация, CORS, rate limit | Критичная |
| Auth-сервис | JWT, RBAC, ABAC, аудит | Критичная |
| Orchestrator | Логика ТПП, точки контроля | Критичная |
| Технологические модули | ТП, ЧПУ, нормы | Высокая |
| Equipment/BOM/Assembly/Recommendation | Данные, рекомендации | Высокая |
| PostgreSQL | Данные, аудит | Критичная |
| RabbitMQ | Обмен сообщениями | Высокая |
| MinIO | Файлы, документы | Высокая |
| Kubernetes | Инфраструктура | Критичная |
| CI/CD (GitLab) | Сборка, деплой | Критичная |
| UI (React + Electron) | Клиентская часть | Высокая |

### 3.2. Типы угроз

- **Внешние:** атаки, сканирование, brute-force.
- **Внутренние:** ошибки пользователей, злоупотребление правами.
- **Технические:** уязвимости, конфигурационные ошибки.
- **Организационные:** утечка через персонал.
- **Supply chain:** компрометация зависимостей.

## 5. Управление доступом

### 5.1. Модель доступа

- **RBAC** — роли: `ADMIN`, `MANAGER`, `ENGINEER`, `NORMER`, `OPERATOR`, `VIEWER`, `INTEGRATION`.
- **ABAC** — атрибуты: `enterpriseCode`, `department`, `ownerId`, `classification`, `stage`.
- **Итоговое решение:** пересечение RBAC и ABAC.

### 5.2. Регламент управления

| Действие | Кто выполняет | Как |
|---|---|---|
| Создание пользователя | ADMIN | UI / API |
| Назначение роли | ADMIN | UI / API |
| Отзыв роли | ADMIN | UI / API |
| Блокировка учётки | ADMIN / автоматически | UI / после N неудач |
| Разблокировка | ADMIN | UI |
| Смена пароля | Пользователь | UI |
| Принудительная смена | ADMIN | UI |
| Удаление пользователя | ADMIN | UI (архивация) |

### 5.3. Политика паролей

- Минимум 12 символов.
- Минимум 3 класса символов (заглавные, строчные, цифры, спецсимволы).
- Смена каждые 90 дней (для привилегированных ролей).
- Запрет повторного использования последних 5 паролей.
- Блокировка после 5 неудачных попыток на 30 минут.

### 5.4. Аудит доступа

Все действия фиксируются в `audit_log`:
- логин/логаут (успех/неудача);
- смена пароля;
- выдача/отзыв ролей;
- изменение прав;
- доступ к критичным данным.

### 5.5. Регулярный аудит прав

**Ежемесячно:**

```sql
-- Пользователи с ролью ADMIN
SELECT u.username, u.email, r.name
FROM iktk.users u
JOIN iktk.user_roles ur ON ur.user_id = u.id
JOIN iktk.roles r ON r.name = ur.role_name
WHERE r.name = 'ADMIN'
ORDER BY u.username;

-- Неактивные пользователи с правами
SELECT username, last_login_at
FROM iktk.users
WHERE enabled = TRUE
  AND (last_login_at IS NULL OR last_login_at < NOW() - INTERVAL '90 days')
ORDER BY last_login_at NULLS FIRST;

-- Пользователи с несколькими ролями
SELECT u.username, COUNT(ur.role_name) AS role_count
FROM iktk.users u
JOIN iktk.user_roles ur ON ur.user_id = u.id
GROUP BY u.username
HAVING COUNT(ur.role_name) > 3
ORDER BY role_count DESC;
