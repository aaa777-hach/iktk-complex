## 1. Видение продукта

**ИКТК** — интегрированный конструкторско-технологический комплекс с программой-оркестратором («дирижёром»), который автоматизирует технологическую подготовку производства (ТПП) от идеи до готовой продукции. Комплекс:

- объединяет разрозненные CAD/CAM/CAPP-системы в единый контур;
- управляет последовательностью проектирования ТП и оснастки;
- анализирует сборочные единицы и строит состав изделия (BOM);
- проверяет реализуемость ТП на парке предприятия;
- предлагает решения при дефиците оборудования (альтернативы, докупка, аутсорс);
- обеспечивает сквозную документацию, аудит и версионность.

**Миссия:** сократить время ТПП и повысить качество технологических решений за счёт интеллектуальной оркестрации и сквозной цифровизации.

### 5.2. MVP (Minimum Viable Product)

**Срок:** 6–8 месяцев.  
**Цель:** запустить базовую оркестрацию ТПП для 4 видов обработки.

#### Функциональность

**Оркестратор:**
- Конечный автомат с 14 состояниями.
- Точки контроля (смешанный режим).
- Журнал решений, аудит.
- Обработка отказов модулей (retry, DLQ).

**Ядро:**
- Доменные модели: проект, ТП, этап, геометрия.
- DTO, валидация, исключения.

**API Gateway:**
- Маршрутизация, CORS, rate limiting.
- Аутентификация JWT.

**Аутентификация:**
- Логин, refresh, logout.
- RBAC (7 ролей) + ABAC (атрибуты).
- Аудит действий.

**Технологические модули:**
- **Casting** — литьё (песчаные формы, кокиль, под давлением).
- **Forging** — объёмная штамповка (горячая, холодная).
- **Machining** — механообработка + ЧПУ (Fanuc, Siemens, Heidenhain).
- **Norming** — нормы времени и расхода материалов.

**Интеграции CAD:**
- Siemens NX / Tecnomatix.
- Dassault DELMIA / 3DEXPERIENCE.
- T-FLEX CAD / DOCs.
- КОМПАС-3D / ЛОЦМАН:PLM.

**UI:**
- Граф ТП (ReactFlow) с редактированием.
- Страница проекта (прогресс, решения, история).
- Реестр оборудования (базовый).
- Дашборд.
- Электронная оболочка (Electron) для локальных интеграций.

**Инфраструктура:**
- PostgreSQL 16, RabbitMQ 3.13, MinIO.
- Kubernetes, GitLab CI.
- Prometheus + Grafana, Loki.

**Документация:**
- ТЗ, архитектура, ERD.
- OpenAPI, руководство пользователя.
- Руководство по развёртыванию.

**Тестирование:**
- Unit (≥ 70 %), integration, e2e (Playwright), load (k6).
- Security (SAST, Dependency-Check, Trivy, Gitleaks).

#### Метрики успеха MVP

- Пользователи могут создать проект и пройти полный цикл ТПП для детали.
- Время ТПП сокращено на 15–20 % (пилот).
- Все критические сценарии покрыты e2e.
- Развёртывание в production воспроизводимо.

#### Ограничения MVP

- Нет поддержки сборок и BOM.
- Нет gap-анализа и рекомендаций.
- Нет каталога внешнего оборудования.
- Нет аутсорса.

### 5.3. Релиз 1

**Срок:** +4–6 месяцев после MVP.  
**Цель:** расширить комплекс на сборку и оборудование, добавить рекомендации.

#### Функциональность

**Оборудование (полный):**
- Реестр предприятия (CRUD).
- Возможности по операциям (точность, габариты, ЧПУ, мощность).
- Состояние и загрузка (1:1).
- Совместимость с оснасткой.
- Массовый импорт из CSV/XLSX.
- Matching: сопоставление требований ТП с парком.
- Gap-анализ: выявление дефицита.

**BOM и сборка:**
- **Bom-service** — извлечение BOM из CAD, дерево состава изделия.
- Анализ сборочной единицы (BOM из Siemens, Dassault, T-FLEX, КОМПАС).
- Ручная корректировка BOM.
- Связи и сопряжения сборки.
- Последовательность установки деталей (топологическая сортировка).
- Спецификация по ГОСТ 2.106.

**ТП сборки (assembly-process-service):**
- Проектирование ТП сборки на основе BOM и связей.
- Операции сборки (установка, крепление, контроль).
- Сборочная оснастка (приспособления, зажимы, фиксаторы).
- Карта сборки.

**Рекомендации (recommendation-service):**
- Gap-анализ по проекту.
- Формирование рекомендаций:
  - альтернативное оборудование;
  - докупка / аренда;
  - аутсорс;
  - корректировка ТП.
- Скоринг вариантов (стоимость, сроки, качество).
- Каталог внешнего оборудования (`vendor_catalog`).
- Варианты аутсорса (`outsourcing_options`).
- Принятие решений: принять / отклонить / скорректировать / аутсорс.

**UI (Релиз 1):**
- BOM-дерево (компонент `BomTree`).
- Страница дефицита и рекомендаций (`EquipmentGapPage`).
- Карточка оборудования (`EquipmentCard`).
- Панель рекомендаций (`RecommendationPanel`).
- Расширенный реестр оборудования.

**Безопасность (дополнительно):**
- Шифрование бэкапов БД.
- Подпись образов (cosign).
- Ограничение Swagger/OpenAPI по IP.
- Централизованный сбор логов (Loki/ELK).

#### Метрики успеха Релиза 1

- Полный цикл ТПП для сборки: от BOM до документации.
- Gap-анализ покрывает 100 % требований ТП.
- Рекомендации формируются автоматически.
- Время ТПП сокращено на 30 % (пилот).
- Ошибки снижены на 40 %.

#### Ограничения Релиза 1

- Нет внешних интеграций (заказчики, подрядчики).
- Нет A/B-тестов.
- Нет библиотеки оснастки.
- Нет mTLS между сервисами.

---

### 5.4. Релиз 2

**Срок:** +6 месяцев после Релиза 1.  
**Цель:** расширить интеграции, повысить безопасность и качество.

#### Функциональность

**Внешние интеграции:**
- API для заказчиков (просмотр статуса проекта).
- API для подрядчиков (передача операций на аутсорс).
- Интеграция с PDM/PLM-системами.
- Интеграция с системами учёта оборудования.

**A/B-тесты технологических решений:**
- Сравнение вариантов ТП.
- Метрики эффективности (время, стоимость, качество).
- Рекомендации по итогам A/B.

**Библиотека оснастки и материалов:**
- Каталог типовой оснастки.
- Каталог материалов с характеристиками.
- Повторное использование решений.

**Безопасность (дополнительно):**
- mTLS между сервисами (service mesh).
- Токены в httpOnly cookies (вместо localStorage).
- Расширенный аудит (детальный `change_log`).
- SIEM-интеграция.

**Производительность:**
- Оптимизация конечного автомата (шардирование).
- Кэширование в Redis.
- Расширенное нагрузочное тестирование.

**UX:**
- Персонализация интерфейса.
- Тёмная/светлая тема.
- Улучшенная эргономика.

#### Метрики успеха Релиза 2

- Внешние интеграции работают в production.
- A/B-тесты дают измеримый результат.
- Библиотека оснастки и материалов используется ≥ 50 %.
- Все сервисы защищены mTLS.

---

### 5.5. Релиз 3

**Срок:** +6–12 месяцев после Релиза 2.  
**Цель:** предиктивная аналитика, интеграция с MES/ERP, распределённые производства.

#### Функциональность

**Предиктивная аналитика:**
- Прогнозирование поломок оборудования (по данным телеметрии).
- Рекомендации по оптимизации ТП на основе накопленных данных.
- Machine Learning для выбора методов обработки.

**Интеграция с MES/ERP:**
- Обмен данными о заказах, парках, материалах.
- Обратная связь о фактических нормах.
- Автоматическое обновление статусов.

**Распределённые производства:**
- Поддержка нескольких предприятий/филиалов.
- Синхронизация реестров оборудования.
- Распределённые очереди и хранилища.

**Расширенная аналитика:**
- Дашборды для руководителей.
- Метрики KPI по ТПП.
- Отчёты по загрузке, стоимости, качеству.

**Расширение ТП:**
- Термообработка, покрытия, сборка (расширенная).
- Вспомогательные ТП.
- Специальные методы (электроэрозия, лазер).

#### Метрики успеха Релиза 3

- Предиктивная аналитика точна ≥ 80 %.
- Интеграция с MES/ERP работает в production.
- Поддержка ≥ 3 распределённых предприятий.
- Расширенная аналитика используется руководством.

## 9. Обратная связь и итерации

### 9.1. Каналы обратной связи

- Пилотные пользователи (фокус-группа).
- Встроенная форма обратной связи в UI.
- Регулярные интервью с инженерами.
- Аналитика использования (какие функции востребованы).
- Метрики производительности и ошибок.

### 9.2. Процесс итераций

1. Сбор обратной связи (еженедельно).
2. Анализ и приоритизация (ежемесячно).
3. Включение в бэклог следующего релиза.
4. Демо и проверка результата.

### 9.3. Принципы развития

- **Customer-first:** решения на основе потребностей пользователей.
- **Data-driven:** метрики определяют приоритеты.
- **Iterative:** маленькие шаги, быстрая обратная связь.
- **Sustainable:** баланс между скоростью и качеством.
- **Extensible:** архитектура готова к расширениям.
