# SecurityCheck — чек-лист тестов безопасности ИКТК

**Проект:** Интегрированный конструкторско-технологический комплекс (ИКТК)  
**Версия ТЗ:** `final_TZ.md` (ред. 3)  
**Область:** безопасность веб-клиента, API Gateway, сервисов, БД, хранилища  
**Дата:** актуально на момент редакции 3  

---

## 1. Назначение

Документ описывает **полный чек-лист проверок безопасности** ИКТК.  
Используется:
- при подготовке к релизу (перед выводом в production);
- в рамках регулярных security-аудитов (ежеквартально);
- в CI/CD — как источник для автоматизированных проверок (позиция 62, стадия `security`);
- при разборе инцидентов ИБ.

**Принятое решение (из `final_TZ.md`, п. 5):** защита КТД как коммерческой тайны **не требуется** (решение C). Риск зафиксирован в `security_audit.md`. Чек-лист учитывает это как **accepted risk** — соответствующие пункты помечены `[ACCEPTED RISK]`.

## 14. Автоматизированные проверки в CI/CD

Интеграция с GitLab CI (позиция 62, стадия `security`):

| Джоба | Инструмент | Что проверяет |
|---|---|---|
| `sast` | Semgrep | статический анализ кода (SQLi, XSS, secrets) |
| `dependency-scanning` | OWASP Dependency-Check | CVE в зависимостях |
| `container-scanning` | Trivy | CVE в образах |
| `secret-detection` | Gitleaks | утечки секретов в репозитории |
| `nightly-security-scan` | Trivy fs | полное сканирование файловой системы |

**Пороги:**
- HIGH/CRITICAL в образах → блокирует merge (в `release/*` и `main`);
- секреты в репозитории → блокирует merge;
- SAST — предупреждение (не блокирует).
